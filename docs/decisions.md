# 決めたこと

議論で決めた方針の記録です。新しく決めたら追記します。

## 目的

- 使う機材（ギター・エフェクター・アンプ）の組み合わせから、出る音を **視覚的に** シミュレーションする
- 実際の音源を解析し、**手持ちの機材の範囲で** 近い音になる設定を提案する（買い物の提案は当面しない）
- 基本は個人用。リハスタ / ライブハウス / レコーディングの使用環境を切り替えられる

## 見せるもの

1. 周波数特性（各機材を通ったあとの帯域）
2. 歪みの量と倍音
3. 音量の変化（ゲインステージ）
4. 時間方向の変化（ディレイ・リバーブの残り方、コンプのかかり方）
5. 電源（消費電流・パワーサプライの割り当て・AC の消費電力）

当面は **見るだけ**。実際に音を鳴らす機能は後回し。

## 音の再現の段階

1. 機材の種類ごとの汎用モデル＋回路の数値からの計算（いまここ）
2. キャビネットの IR ファイルの読み込み
3. 実機を学習したデータ（Neural Amp Modeler など）の読み込み

## 機材情報の取り込み

- 入力は「一覧から選ぶ」方式。製品ページや説明書の URL から、つまみ・電源・入出力などを読み取る
- 回路の扱いは **製品ごとに最も適した方法** を選ぶ
  - 回路が分かるもの → 回路の数値から計算（例：アンプのトーン回路）
  - 公開仕様で足りるもの → 仕様の数値をそのまま使う（例：バッファ・ブースター）
  - デジタル機材 → 回路解析は不要。設定値をそのまま使う
  - 回路が非公開のもの → 汎用モデルで仮置きし、実機測定で置き換える
- 数値ごとに出典と確認状況（確認済 / 要確認 / 未取得）を必ず表示する。見つからない数値を推測で埋めない
- URL の読み取りと音源からのギター分離はブラウザだけでは動かないため、小さなサーバーを置く（AI の利用料がかかることは了承済み）

## 音源解析と提案

1. 曲からギターの音だけを取り出す（Demucs など）
2. 帯域バランス・歪みの量・コンプ感・残響の長さなどを数値にする
3. 手持ちの機材のつまみの組み合わせを探し、目標に近い設定を出す
4. 提案は「ここから始めると近い」という出発点として扱い、差分グラフも一緒に見せる

## UI

- A 案（実機の並び・つまみ）と B 案（解析グラフ＋インスペクタ）を組み合わせる
- AI っぽさを避ける：Web フォントを使わず OS 標準の文字、無彩色のグレー、色は信号の状態（ON・クリップ・注意）とグラフの線だけ、角丸・光る効果・色付きバッジを使わない
- つまみは「0〜10」と「時計の何時」を並べて表示
- ON/OFF はフットスイッチ型のボタンで、OFF の機材は暗く・破線・薄く表示
- キーボード操作に対応
- セッティングシートの出力（ローディーや PA に渡す用）は今後実装

## 動かす場所

- まずブラウザ。ゆくゆくはアプリ化
